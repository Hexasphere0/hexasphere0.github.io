Today, I decided to get multiplayer to work. Previously, I tried getting it to work, but I ran into several issues that I couldn't understand, especially with input. The input system simply did not work no matter what I tried. I debugged the issue and found that the action maps were not loading, which made no sense, as the player input component should have kept them loaded even between scene changes. I put all that work on a branch so I could debug again when I could figure out what was going wrong.

Instead, today, I decided to go for a different route and simply reimplement multiplayer from scratch, debugging as I went in order to catch any issues and fix them. Previously, I implemented pretty much everything before testing, which made it really hard to figure out what I did wrong. I started by removing the project wide input actions. While these worked great in the past, they did not work with multiplayer and had to be removed. I refactored the player class to instead read input from a input map that I enable when the player object is created. Basically, Unity allows you to create a C# class based on the input actions you register in a map. You can then enable the class and read from it directly. As each player object handles its own input, this works perfectly in multiplayer. 

The next big issue is that the player class was using singleton logic previously. This obviously wouldn't work, as multiplayer requires for multiple players to work. Thankfully, as all of the physics scripts go on the player object, I can simply use get component to get the player controller class instead of relying on an instance. However, updating the level management scripts was quite tricky. Currently, I have most of their functionality commented out for updating in the future, as making it work with multiple players requires a lot more refactoring. I then updated or commented out all other scripts that required the singleton player. Now that this was out of the way, I copied the join code premade multiplayer scene, added my player object, and tried it out. When my friend tried to join the lobby, we got an issue saying that the network manager failed to initialize. After searching this up, I figured out that it was caused by differences in configuration. The problem was that he had an extra prefab in his network prefabs list, which didn't really make sense because it should have synced through git, but at least it was an easy fix.

We tried again, and this time both of our player objects were in the scene, but there were a couple issues. First, the camera logic was completely broken, as previously I just hard coded the player object into the Cinemachine follow target. As the player object is now instantiated by the network manager, this doesn't really work anymore. I decided to fix this by having a script on the player that found the first Cinemachine component in the scene on start, and set its follow target. This fixed that issue. The other issue was that I controlled both players movements. This was an issue I actually anticipated, because I never added logic to make it so only the owner of a player object could move it. That was pretty easy to fix too. Then, I added a block to the lobby that when touched teleported all players into an actual level. 

However, when we teleported into the actual level, there were several issues. First, the spawn point was completely wrong, and second, the camera broke again. I still haven't fixed the spawn point, as that would require updating the level management code, which I plan on doing tomorrow. As we could just drag our player objects around in the editor, I decided I could wait on fixing this. The camera was way harder to fix. Initially, I realized that the new camera in the level that was just loaded never got its target assigned. I added code to the player to simply assign the camera both on spawn and when a scene is loaded. This still didn't work. I could see my code executing, but not actually setting the camera follow target. After some debugging, I decided that the issue was caused because the player was trying to assign the camera target before it fully initialized, and was overwritten later. I redid the code so the script to assign the target went on the camera, and could simply run when the camera enabled. This fixed these issues, but we ran into another issue pretty soon.

As the level management system was disabled, so were checkpoints. I made a quick fix to simply make the checkpoint change your respawn point when you touch them, but this whole system will need a lot of fixing. For now, we were able to play through the level pretty seamlessly.
